# Activity Line Chart Design

## Goal

Replace the contribution-style dot map with a compact, smoothed cumulative line chart that makes overall commit growth easy to read without hiding each day's commit contribution.

## Data range

The chart uses the activity dates actually present in the retrieved cache. Its left boundary is the oldest retrieved commit date and its right boundary is the most recent retrieved commit date. Every calendar date between those boundaries is represented, including zero-commit days.

If the activity cache is empty, the chart shows a quiet empty state rather than inventing a date range. A single-day dataset remains visible as one centered point.

## Visual design

The chart remains inside the existing Activity Overview glass card. The header displays the oldest date on the left and the most recent date on the right, with the chart title retained as the primary label.

The plot uses a smooth emerald line with a restrained green area fade beneath it. Its height represents cumulative commits, so it rises as commits are added and remains flat on zero-commit days; it never descends. Faint horizontal guides establish scale without adding a labeled axis. The line is the signature element; surrounding decoration stays subdued.

Daily observations are represented by small interaction targets. Points remain visually quiet until hover or keyboard focus, when the selected point brightens, enlarges, and gains a vertical guide.

## Interaction

Hovering a daily point reveals the existing floating tooltip with the formatted date, commits added that day, and the cumulative total through that date. The daily value is primary and the cumulative value is secondary. The tooltip follows the selected point while remaining inside the window bounds.

Pointer movement across the plot selects the nearest calendar day, so zero-commit days and densely packed dates are still inspectable. Keyboard users can focus the chart and use the left and right arrow keys to inspect the same daily points and tooltip content.

The chart exposes an accessible label describing the date range and final cumulative total. The selected point is announced through the tooltip's live status text.

## Rendering

The implementation uses inline SVG generated by `buildActivityMap`, with no new runtime dependency. Pure helper functions convert sparse daily counts into a continuous calendar series, calculate the cumulative total for each day, and produce a monotone cubic path without visual decreases or overshoot.

The renderer derives SVG coordinates from the activity container's live width. It preserves internal padding for point targets and resizes by rebuilding the chart when the widget width changes.

The previous grid cells, month labels, intensity legend, and activity-color helper are removed. The existing tooltip element is reused.

## Verification

Unit and contract tests will require a continuous cumulative series, a non-descending smooth path, an SVG chart, oldest/latest retrieved date labels, daily point markers, and accessible interaction. Runtime verification will confirm the actual Electron widget renders the expected number of daily points, hover reveals both the daily and cumulative values, keyboard navigation works, resize remains contained, and the console stays free of errors.
