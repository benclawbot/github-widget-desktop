# Activity Line Chart Design

## Goal

Replace the contribution-style dot map with a compact, smoothed line chart that makes daily commit volume easier to read without changing the widget's existing dark GitHub-inspired visual language.

## Data range

The chart uses the activity dates actually present in the retrieved cache. Its left boundary is the oldest retrieved commit date and its right boundary is the most recent retrieved commit date. Every calendar date between those boundaries is represented, including zero-commit days.

If the activity cache is empty, the chart shows a quiet empty state rather than inventing a date range. A single-day dataset remains visible as one centered point.

## Visual design

The chart remains inside the existing Activity Overview glass card. The header displays the oldest date on the left and the most recent date on the right, with the chart title retained as the primary label.

The plot uses a smooth emerald line with a restrained green area fade beneath it. Faint horizontal guides establish scale without adding a labeled axis. The line is the signature element; surrounding decoration stays subdued.

Daily observations are represented by small interaction targets. Points remain visually quiet until hover or keyboard focus, when the selected point brightens, enlarges, and gains a vertical guide.

## Interaction

Hovering or focusing a daily point reveals the existing floating tooltip with the formatted date and commit count. The tooltip follows the selected point while remaining inside the window bounds.

Pointer movement across the plot selects the nearest calendar day, so zero-commit days and densely packed dates are still inspectable. Keyboard users can tab through daily points and receive the same tooltip content.

The chart exposes an accessible label describing the date range and total number of daily observations. Each point exposes its date and commit count through an accessible label.

## Rendering

The implementation uses inline SVG generated by `buildActivityMap`, with no new runtime dependency. A monotone cubic curve produces smooth transitions without overshooting below zero or above the observed daily maximum.

The renderer derives SVG coordinates from the activity container's live width. It preserves internal padding for point targets and resizes by rebuilding the chart when the widget width changes.

The previous grid cells, month labels, intensity legend, and activity-color helper are removed. The existing tooltip element is reused.

## Verification

Contract tests will require an SVG chart, a smooth path, oldest/latest retrieved date labels, daily point interaction targets, and accessible labels. Runtime verification will confirm the actual Electron widget renders the expected number of daily points, hover reveals the correct date and count, resize remains contained, and the console stays free of errors.
